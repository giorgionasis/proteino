# Proteino — Quick Context

Mobile-first community recommendation platform (Greek market). Users suggest and discover books, movies, series, recipes, food, bars, hotels, theater, events. AI-powered submission + search flows.

**Stack:** Next.js 16 (App Router + Turbopack) + React 19 + Tailwind + Supabase (PostgreSQL + Auth + Storage). Node 22 LTS.

**Current state (session 35):** Auth + extension tables + 1955 items / 627 users. Search v2 (Gemini), submission v2, notifications dispatcher, security settings, region picker, achievement celebration (suggestions + reviews + per-category + streak milestones), onboarding, moments, submission funnel, admin-controlled layouts via `page_sections`, admin-configurable related-section carousels, Google rich-results SEO, admin-editable category metadata (label/icon/order/nav) via `category_meta` resolver, structured amenities filter (food/bars/hotels) reading from existing `information.amenities` + `facilities` columns, manual-list mode for Collections via Explorer matched-IDs handoff (localStorage) — all shipped. Runtime is Node 22 LTS + React 19.2.6 + Next 16.2.6 (Turbopack) + React Compiler 1.0.

(1) **Admin flash fix** on `/admin/categories` + `/admin/content/filters` — the new session-34 pages were `"use client"` components mounting empty and fetching in useEffect; fixed by making `page.tsx` async server components that pre-fetch initial data (including the empty-selection Explorer query), pass it as `initial*` props, and use `useRef` skip-flags to suppress the first-mount fetch. CLAUDE.md §52. (3) **Vibes tag-pattern filter (043) — shipped then reverted.** User pushback ("we search specifically for a bar if it has a roof garden") — filtering should be structured queries, not regex over tags. Rollback migration drops the seed if applied. CLAUDE.md §53. (4) **Structured amenities filter** — the proper replacement. Crucial discovery: the data already exists in `item_food.information.amenities` / `item_bars.information.amenities` / `item_hotels.facilities`. No schema migration needed; just denormalised `CategoryItem.amenities`, wired `EXT_SELECT` to pull `information`, added `case "amenities"` to `matchesFilter` with AND semantics via the existing `parseAmenities` helper, seeded 3 public filter rows via migration 044. "Roof Garden" on `/bars` now selects bars where `amenities.roof_garden=true` — hard yes/no. CLAUDE.md §53.B. **🎯 Next move — AI search v3 (CLAUDE.md §54):** the structured amenities filter only matters if users can find chips. Most users type instead. Today's Gemini extractor pulls intent / vibe / type / location / categories / genre / channel / status / period / person / decade / price / duration — but NOT amenities, NOT seasons, NOT single_season / completed / true_story / diet / when / has_awards. So "χαλάνδρι μπαρ ταράτσα" today returns every Χαλάνδρι bar; the amenity token is dropped. The fix: extend `SearchAnalysis`, teach Gemini the amenity vocabulary (`lib/ai/taxonomy.ts` injection generated from `lib/icons.ts` catalogues), bump `PROMPT_VERSION` to invalidate the 30-day cache, apply the new fields in `app/api/search/route.ts` (venue branch: AND amenities via `parseAmenities`; non-venue: seasons-eq, end_date IS NOT NULL, etc). The structured data is already on items — search just needs to learn how to ask for it. ~2h.
